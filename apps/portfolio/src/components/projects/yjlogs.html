Next.js 16 · TypeScript · TailwindCSS · Drizzle · Neon · Clerk · Cloudflare R2 · Vercel · pnpm · Turborepo

개요

글을 쓰고, 출시한 앱의 랜딩 페이지를 두고, 지원할 때 보여줄 이 포트폴리오를 올려두는 곳이다. 프론트엔드부터 DB, 인증, 이미지 스토리지, 배포, SEO, 유입 분석까지 직접 구성했다.

yjlogs.com 홈
홈. 최신 글과 앱 랜딩으로 이어진다.

문제

  • 회사에서는 백엔드가 있었다. 혼자 만들 때 "어떤 DB, 어떤 인증, 어떤 스토리지"를 스스로 고르고 그 선택을 책임지는 경험이 필요했다.
  • 앱 랜딩 페이지가 없어서 스토어 밖에서 앱을 설명할 곳이 없었다.
  • 나중에 포트폴리오를 같은 도메인에 두고 싶었다. 블로그와 포트폴리오는 스택이 달라 한 앱 안에 넣기 어려웠다.

접근과 선택

영역 선택 이유
데이터 Neon PostgreSQL + Drizzle ORM 서버리스 Postgres라 유휴 비용이 없고, Drizzle은 스키마가 곧 타입이라 별도 코드 생성이 없다
인증 Clerk 관리자 한 명뿐이다. 직접 만들 이유가 없고, 세션·미들웨어를 바로 얻는다
이미지 Cloudflare R2 S3 호환에 egress 무료. 도메인이 이미 Cloudflare라 assets 서브도메인 연결이 한 줄
배포 Vercel Next.js 기본 경로. 저장소 하나에 프로젝트 여럿을 붙일 수 있어 포트폴리오를 서브도메인으로 분리
저장소 pnpm workspace + Turborepo 블로그(Next.js)와 포트폴리오(Vite)를 한 저장소에 두되, 바뀐 앱만 빌드·배포하기 위해
포트폴리오를 블로그 라우트로 넣지 않고 별도 앱으로 뺀 이유는 인쇄 품질이다. 블로그의 루트 레이아웃(인증·분석·테마)이 PDF에 끼어들지 않아야 했다.

구현

저장소 하나, Vercel 프로젝트 둘, 외부 서비스 넷.
  • SEO. 사이트맵, JSON-LD, OG 이미지 자동 생성. GA4로 유입을 본다. 포트폴리오는 반대로 noindex와 robots.txt로 검색에서 뺀다.
  • 모노레포 전환. 기존 저장소를 apps/web으로 옮기고 pnpm과 Turborepo를 얹었다. Vercel은 프로젝트별 Root Directory로 연결하고, 그 디렉터리와 무관한 커밋의 빌드는 Vercel의 Skip deployments가 건너뛴다.
  • 포트폴리오 앱. HTML 파티셜을 빌드 시 하나로 합치는 구조. 같은 HTML이 웹이자 PDF다.

결과

  • yjlogs.com 운영 중. 앱 랜딩 2개, 글, 시리즈, 관리자 화면.
  • portfolio.yjlogs.com에 이 문서. 블로그만 고친 커밋에는 포트폴리오가 배포되지 않는다.
글 상세 페이지
글 상세. 코드 하이라이트와 목차, 댓글.

회고

서비스를 고를 때 "직접 만들 수 있는가"보다 "혼자 운영할 수 있는가"를 기준으로 삼은 것이 맞았다. 인증과 스토리지를 직접 만들었다면 지금 글을 쓰는 대신 그걸 고치고 있었을 것이다. 모노레포는 앱이 둘뿐이라 Turborepo의 이득이 아직 작다. 공유 패키지가 생기면 그때 진가가 나온다.
